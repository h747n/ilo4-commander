# iLO4 Commander 3

یک پنل برای **همه‌ی** سرورهای HPE ProLiant Gen8/Gen9 که iLO 4 پچ‌شده دارند: کنترل فن با منحنی دما، تاریخچه‌ی کامل حسگرها، نسخه‌ی موبایل (PWA و APK اندروید). دیگر لازم نیست برای هر سرور یک VM جدا داشته باشی؛ یک سرویس روی یک VM همه را مدیریت می‌کند.

## چه چیزی نسبت به نسخه‌ی ۲ عوض شد

| مشکل در نسخه‌ی ۲ | در نسخه‌ی ۳ |
|---|---|
| بعد از خاموش و روشن شدن سرور باید تیک منحنی را دوباره می‌زدی | پنل تغییر PowerState و PostState را تشخیص می‌دهد و تنظیمات را خودش دوباره می‌فرستد: یک بار در لحظه‌ی روشن شدن، یک بار وقتی POST تمام شد و دو بار دیگر یک و سه دقیقه بعد. اگر iLO خودش ریست شود (لاگین دوباره‌ی SSH) یا فن‌ها چند بار پشت سر هم تندتر از سقف بچرخند هم همین کار انجام می‌شود. برای احتیاط هم هر ۵ دقیقه یک بار تنظیمات فرستاده می‌شود. تنظیمات دستی (بدون منحنی) هم بعد از ریبوت برمی‌گردند. |
| اتصال Redfish مدام قطع و وصل می‌شد | هر تب مرورگر یک حلقه‌ی جدا روی iLO راه می‌انداخت و هر درخواست با Basic Auth لاگین تازه می‌کرد، و شمارش فن‌ها هر چند ثانیه یک فرمان SSH می‌فرستاد. حالا برای هر سرور فقط یک worker با iLO حرف می‌زند، یک بار لاگین می‌کند و session token را نگه می‌دارد، سوکت‌های بیکار را پیش از آنکه iLO ببندد دور می‌اندازد و فقط بعد از ۳ خطای پشت سر هم وضعیت را «down» می‌کند. مرورگرها و اپ موبایل فقط snapshot آماده را می‌خوانند. |
| Watchdog بعد از قطع کردن، منحنی را برای همیشه خاموش می‌کرد | حالا منحنی فقط متوقف می‌شود و وقتی همه‌ی حسگرها خنک شدند خودش دوباره فعال می‌شود (قابل خاموش کردن است). |
| یک VM برای هر سرور | یک سرویس برای همه. سرورها از داخل پنل اضافه، ویرایش، موقتاً متوقف یا حذف می‌شوند. |
| ۱۱ تب | فقط Overview، Sensors، History، Fans و Tuning. |
| History ساده | بازه‌های ۱ ساعت، ۶ ساعت، ۱ روز، ۱ هفته، ۱ ماه و ۳ ماه، رفتن به عقب و جلو یا یک تاریخ دلخواه، نوار min/max، خواندن مقدار با نگه داشتن ماوس یا انگشت، نشانه‌گذاری رویدادها (ریبوت، Watchdog، قطعی) روی نمودار، جدول min/avg/max و خروجی CSV. |
| Tuning بدون توضیح | راهنمای فارسی برای هر بخش، روال قدم‌به‌قدم امن و بخش سؤال‌های رایج. |
| فقط دسکتاپ | چیدمان موبایل با نوار تب پایین، قابل نصب به‌صورت PWA و APK اندروید. |

## نصب (روی یک VM لینوکسی با systemd)

```bash
# پوشه‌ی پروژه را روی VM کپی کن، بعد:
cd ilo4-commander
sudo ./install.sh
```

نصب‌کننده پورت وب، رمز پنل و در صورت تمایل گواهی HTTPS را می‌پرسد. سرویس در `/opt/ilo4-commander` نصب می‌شود و با کاربر سیستمی `ilo` اجرا می‌شود. بعد پنل را باز کن و از آیکن چرخ‌دنده گزینه‌ی **+ Add server** را بزن. با دکمه‌ی **Test connection** قبل از ذخیره، Redfish، SSH و پچ بودن فریمور بررسی می‌شوند.

اجرای دوباره‌ی `sudo ./install.sh` یعنی **ارتقا**: کد عوض می‌شود ولی `.env`، سرورها، منحنی‌ها و تاریخچه دست نمی‌خورند.

نیازمندی‌ها: Python 3.9 یا جدیدتر و `python3-venv` (روی Ubuntu و Debian: `sudo apt install python3-venv`).

داکر هم پشتیبانی می‌شود: `sudo ./install.sh --mode docker`

## انتقال از VM های قدیمی (نسخه‌ی ۲)

از هر VM قدیمی فقط پوشه‌ی نصب لازم است (`.env` و `data/`). آن‌ها را روی VM جدید کپی کن:

```bash
scp -r root@old-vm-1:/opt/ilo4-commander /tmp/rack1-dl380
scp -r root@old-vm-2:/opt/ilo4-commander /tmp/rack1-dl360
sudo ./install.sh --migrate /tmp/rack1-dl380 /tmp/rack1-dl360
```

برای هر پوشه، سرور با آدرس و رمز iLO اضافه می‌شود و منحنی‌ها، پریست‌ها، آخرین تنظیمات دستی و **کل تاریخچه‌ی ثبت‌شده** هم منتقل می‌شوند. اسم سرور همان اسم پوشه می‌شود و بعداً در پنل قابل تغییر است.

> **مهم:** بعد از انتقال، سرویس VM های قدیمی را خاموش کن (`systemctl disable --now ilo4-commander`). اگر دو برنامه هم‌زمان به یک iLO فرمان فن بدهند، با هم می‌جنگند و بار iLO هم دو برابر می‌شود.

## اپ موبایل

دو راه داری:

### ۱) PWA (بدون نصب فایل)
پنل را در Chrome اندروید یا Safari آیفون باز کن و از منو گزینه‌ی *Install app* یا *Add to Home Screen* را بزن. **شرط:** مرورگرها فقط روی HTTPS اجازه‌ی نصب PWA می‌دهند. هنگام نصب، مسیر گواهی و کلید را بده، یا بعداً در `/opt/ilo4-commander/.env` این دو خط را پر کن:

```
SSL_CERT=/etc/ssl/internal/panel.crt
SSL_KEY=/etc/ssl/internal/panel.key
```

و `sudo systemctl restart ilo4-commander` بزن. گواهی داخلی خودت (CA داخلی) باید روی گوشی trusted باشد.

### ۲) APK اندروید
پوشه‌ی `mobile/` یک اپ Capacitor است. بار اول آدرس پنل را می‌پرسد (مثلاً `http://192.168.1.50:8080`)، همان را به خاطر می‌سپارد و از آن به بعد پنل را تمام‌صفحه باز می‌کند. با **HTTP معمولی هم کار می‌کند** و به گواهی نیاز ندارد. برای عوض کردن آدرس: چرخ‌دنده، بعد *Change panel address*.

**دانلود آماده:** آخرین نسخه همیشه از این لینک دانلود می‌شود:
https://github.com/h747n/ilo4-commander/releases/download/android-latest/ilo-fans.apk

ساختن APK خودت:

- **بدون نصب هیچ چیز (پیشنهادی):** روی fork خودت در تب Actions گزینه‌ی **Android APK → Run workflow** را بزن. APK در قسمت Artifacts اجرای تمام‌شده و در Release با نام `android-latest` قرار می‌گیرد.
- **روی سیستم خودت:** به Node 18 یا جدیدتر، JDK 17 و Android SDK (با متغیر `ANDROID_HOME`) نیاز داری:
  ```bash
  cd mobile
  npm install
  npm run build:apk     # خروجی: mobile/dist/ilo-fans.apk
  ```

APK با کلید debug امضا شده و مستقیم نصب می‌شود. باید در گوشی گزینه‌ی «نصب از منابع ناشناس» را برای مرورگر یا فایل‌منیجر فعال کنی.

## تب‌ها

- **Overview**: کارت همه‌ی سرورها (وقتی بیش از یکی داری)، اینکه الان چه کسی فن‌ها را کنترل می‌کند، دکمه‌های *Re-send* و *Hand back to iLO*، قفسه‌ی فن که با کشیدن سقف هر فن عوض می‌شود، داغ‌ترین حسگرها، نمودار یک ساعت اخیر و کارت **Activity** (ریبوت‌ها، ارسال دوباره‌ی تنظیمات، Watchdog و قطعی‌ها).
- **Sensors**: همه‌ی حسگرها گروه‌بندی‌شده با sparkline. با زدن روی هر کارت تاریخچه‌ی همان حسگر باز می‌شود. اطلاعات فن‌ها و منبع تغذیه هم اینجاست.
- **History**: هر حسگر دلخواه (دما، فن، توان و خروجی منحنی) در هر بازه‌ای. داده‌ها ۴۸ ساعت با دقت کامل نگه داشته می‌شوند (قابل تنظیم)، ۳۵ روز به‌صورت میانگین ۵ دقیقه‌ای و ۲ سال به‌صورت ساعتی. حجم دیتابیس کوچک می‌ماند.
- **Fans**: منحنی‌های خودکار (هر منحنی حسگر خودش را دارد و هر فن به یک منحنی وصل است)، تنظیم Hysteresis و Ramp، کنترل دستی و پریست‌ها.
- **Tuning**: دستورهای خام کنترلر فن iLO همراه با راهنمای فارسی.

## تنظیمات هر سرور

در *Servers & settings → Edit → Advanced*:

| گزینه | پیش‌فرض | توضیح |
|---|---|---|
| Poll interval | ۱۰ ثانیه | هر چند ثانیه دما خوانده و منحنی اعمال شود. اگر iLO کند است، ۱۵ تا ۲۰ بگذار. |
| Lowest fan % allowed | ۸ | پنل هیچ‌وقت عددی کمتر از این به فن نمی‌فرستد. |
| Watchdog margin | ۵ درجه | اگر حسگری به «Caution منهای این عدد» برسد، کنترل به iLO برمی‌گردد. |
| Re-send every | ۵ دقیقه | ارسال دوره‌ای تنظیمات برای احتیاط. ۰ یعنی خاموش. |
| Monitoring enabled | روشن | با خاموش کردنش سرور موقتاً کنار گذاشته می‌شود، بدون اینکه حذف شود. |

## فایل‌ها و داده‌ها

```
/opt/ilo4-commander/
  .env                     تنظیمات خود پنل (پورت، رمز، HTTPS)
  data/servers.json        فهرست سرورها با رمز iLO (مجوز 600)
  data/servers/<id>/       منحنی، پریست‌ها و آخرین تنظیمات دستی هر سرور
  data/history.db          تاریخچه‌ی همه‌ی سرورها (SQLite)
  data/influx.json         تنظیمات ارسال به InfluxDB
```

بکاپ گرفتن یعنی کپی کردن پوشه‌ی `data/`.

## InfluxDB و Grafana

در *Servers & settings → Send to InfluxDB* فعال می‌شود. تگ `host` حالا **اسم سرور** است، نه آدرس iLO. داشبورد آماده در `grafana/ilo4-dashboard.json` قرار دارد. اگر بیش از یک سرور داری، برای اینکه خط‌ها قاطی نشوند یک متغیر `host` به داشبورد اضافه کن و به queryها `WHERE "host" =~ /^$host$/` اضافه کن.

## عیب‌یابی

```bash
journalctl -u ilo4-commander -f          # لاگ زنده
systemctl restart ilo4-commander
curl -s localhost:8080/api/auth          # آیا پنل جواب می‌دهد؟
```

- **اپ موبایل وصل نمی‌شود:** گوشی باید در همان شبکه یا VPN باشد و پورت پنل در فایروال VM باز باشد (`sudo ufw allow 8080/tcp`).
- **«unpatched»:** SSH وصل است ولی فرمان `fan` وجود ندارد. فریمور iLO پچ نشده است.
- **همچنان قطعی Redfish:** بخش «اتصال Redfish مدام قطع و وصل می‌شود» در تب Tuning را ببین.

## API

مستندات کامل: `http://<panel>/api/docs`. چند نمونه:

```bash
P=http://panel:8080/api; S=rack1-dl380-a1b2c3      # شناسه‌ی سرور از GET $P/servers
curl -s $P/servers
curl -s -X POST $P/servers/$S/fan/pwm -H 'Content-Type: application/json' -d '{"fan":"all","percent":25,"mode":"max"}'
curl -s -X POST $P/servers/$S/fan/reapply
curl -s -X POST $P/servers/$S/fan/restore
curl -s "$P/history/query?server=$S&kind=temp&name=02-CPU%201&range=7d"
```

اگر رمز پنل گذاشته‌ای، اول با `POST /api/login` کوکی بگیر (`-c cookies -b cookies`).

## امنیت

- **حتماً برای پنل رمز بگذار** (`UI_PASSWORD` در `.env`). هر کسی که به پنل دسترسی داشته باشد می‌تواند فن‌های همه‌ی سرورها را کنترل کند. بعد از ۵ رمز اشتباه از یک IP، ورود برای ۵ دقیقه بسته می‌شود.
- رمزهای iLO در `data/servers.json` (با مجوز 600) ذخیره می‌شوند و هیچ‌وقت به مرورگر فرستاده نمی‌شوند. اگر آدرس، پورت یا نام کاربری یک سرور را عوض کنی، باید رمز را دوباره وارد کنی، تا رمز ذخیره‌شده به آدرس دیگری فرستاده نشود.
- درخواست‌های تغییر (POST/PUT/DELETE) و WebSocket فقط از خود پنل پذیرفته می‌شوند. سایت دیگری که در همان مرورگر باز است نمی‌تواند فن‌ها را کنترل کند.
- ارتباط پنل با iLO روی HTTPS و SSH است، ولی گواهی iLO بررسی نمی‌شود، چون iLO 4 گواهی self-signed دارد. ارتباط مرورگر با پنل فقط وقتی رمزنگاری می‌شود که `SSL_CERT` و `SSL_KEY` را تنظیم کرده باشی.
- اگر پنل را پشت reverse proxy می‌گذاری، آدرس proxy را در `TRUSTED_PROXIES` بنویس.

## هشدار

این پنل محافظت حرارتی خود سرور را دور می‌زند. فن‌ها را کم‌کم پایین بیاور، زیر بار کامل تست کن و Watchdog را روشن نگه دار.
